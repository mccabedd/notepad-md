## What this project is

A Notepad-like desktop app for viewing and editing Markdown (`.md`/`.markdown`/`.txt`) files, with a live, directly-editable preview pane. Built with **Rust + Tauri v2** (native OS WebView2 on Windows, no bundled Chromium) — the whole app is a single ~3–4 MB executable instead of the 250–300 MB an Electron equivalent would produce.

- `ui/` — static frontend: `index.html`, `renderer.js` (all app logic, no framework), `styles.css`, `vendor/` (marked.js for Markdown rendering, turndown.js + turndown-plugin-gfm for HTML→Markdown conversion). This is the whole UI; there is no build step for the frontend, it's loaded directly by the WebView.
- `src-tauri/` — Rust backend: `src/main.rs` (native menu setup + all `#[tauri::command]` file-I/O / OS-integration commands), `Cargo.toml`/`Cargo.lock`, `tauri.conf.json`, `capabilities/default.json`, `icons/`.
- `README.md` — user-facing feature list and build instructions, kept up to date with every change.
- `sample.md` — a sample file for manual testing.

## Prerequisites to build (Windows)

- [Rust](https://rustup.rs) (stable, MSVC toolchain)
- MSVC Build Tools ("Desktop development with C++")
- On this dev machine, `cargo` wasn't on PATH by default in the shell used for builds — had to run `$env:PATH += ";$env:USERPROFILE\.cargo\bin"` before `cargo build` in PowerShell. Check if the new machine needs the same workaround.

```bash
cd src-tauri
cargo build --release
```

Executable lands at `src-tauri\target\release\notepad-md.exe` (the `target/` directory is NOT included in this zip — it's regenerated by the build and is huge; first build will download/compile dependencies including `tauri`, `tauri-plugin-dialog`, `tauri-plugin-clipboard-manager`, and `open`).

For faster iterative dev builds: `cargo run` from `src-tauri/`.

## How this app evolved (so you understand *why* things are the way they are)

This started as an Electron app and was rewritten from scratch in Rust/Tauri for size reasons. Development proceeded in rounds of user feedback, roughly:

1. **Phase 0** — Initial Rust/Tauri rewrite. Removed on-screen toolbar (menu-only access), made the Markdown preview directly editable with two-way sync back to the raw source, thin theme-colored scrollbars/caret.
2. **Phase 1** — Added a toggleable toolbar (off by default, View > Toolbar), made the editable Preview the default view, added 4 layout modes (Preview Only / Edit Only / Preview Left+Edit Right / Edit Left+Preview Right) with a resizable split divider.
3. **Phase 2** — Added a multi-document tab bar (only appears when >1 doc is open) with per-tab close buttons, dirty-dot indicator, `Ctrl+Tab`/`Ctrl+Shift+Tab` to cycle, `Ctrl+W` to close.
4. **Phase 3** — Fixed cut/copy/paste toolbar icons, fixed a broken Find feature, added preview-pane line numbers, removed a redundant "Task" toolbar command (kept Checklist), replaced a blocked native `<select>` heading dropdown with H1–H4 buttons.
5. **Phase 4** — `Ctrl+T` toolbar toggle; Table/Code toolbar icons; a hover-reveal copy button on code blocks in the preview; fixed a Find bug where `window.getSelection().addRange()` was stealing focus (replaced with non-focus-stealing `<mark>`-wrapping of matches); converted all toolbar icons from emoji to monochrome `stroke="currentColor"` SVGs (so they adapt to light/dark theme); **moved all keyboard shortcut handling into a single JS `document.addEventListener('keydown', ...)` handler as the one source of truth**, and set the native Tauri menu's accelerator strings to `None` to stop them double-firing with the JS handler; added `.txt` to the Open-dialog filter and CLI-arg handling.
6. **Phase 5** — User reported the menus had lost their shortcut-hint text (a side effect of #4's `None` accelerators) — restored `Some("CmdOrCtrl+...")` accelerator strings on the native menu items *purely so the hint text displays again* (the JS handler is still what actually executes every shortcut; empirically, on this Windows/WebView2 setup, native menu accelerators do not intercept keystrokes before the webview sees them, so there's no double-fire — a debounce guard (`debounceAction` helper in `renderer.js`) was added to the toggle-style actions as cheap insurance anyway). Also: removed toolbar-visibility `localStorage` persistence entirely so the toolbar is unconditionally hidden on every launch; added clickable links in the preview that open in the system's default browser via a new `cmd_open_url` Tauri command (uses the `open` crate, scoped to `http://`/`https://` only, no shell string interpolation); fixed the code-block copy button so it stays visually pinned at the top-right of the block while the code scrolls horizontally underneath it (moved `overflow-x: auto` from `<pre>` onto the inner `<code>` element, since the button is positioned relative to `<pre>`).
7. **Phase 6 (most recent, small follow-up)** — Changed the Find shortcut from `Ctrl+H` to `Ctrl+F`. Changed the Increase Font Size menu's displayed shortcut from "Ctrl+=" to "Ctrl++" — this required manually embedding the hint text in the menu item's title as `"Increase Font Size\tCtrl++"` with the accelerator itself set to `None`, because the underlying Win32 menu library (`muda`, via Tauri) has no way to *display* "+" for that physical key — it always renders the `Equal`/`Minus` key codes as literal `=`/`-` text regardless of what accelerator string you pass it. (Decrease Font Size stays `Ctrl+-`, which already displayed correctly.) The actual keybinding logic for both was never affected — the JS handler already matched on `e.key === '=' || e.key === '+'` and `e.key === '-'`.

## Key architectural decisions to preserve (don't accidentally re-break these)

- **JS `keydown` handler in `renderer.js` is the single source of truth for every keyboard shortcut.** Native Tauri menu accelerator strings in `main.rs` are cosmetic hint text only — never assume setting one is "wiring up" a shortcut; the JS handler (search for `document.addEventListener('keydown'` in `ui/renderer.js`) must also be updated.
- **Toolbar visibility is intentionally not persisted** (`toggleToolbar()` in `renderer.js` no longer writes to `localStorage`, and `restorePrefs()` no longer reads a `toolbar-visible` key) — it must always start hidden. Don't re-add persistence for this without the user asking.
- **External links**: only `cmd_open_url` (Rust, `open` crate, http/https-only validation) may open URLs — don't shell out or use `window.open`.
- **Code-copy-button CSS**: the scroll container for code blocks is `.preview pre code` (not `.preview pre`) — if you touch that CSS, keep the button's positioning ancestor (`<pre>`) non-scrolling.
