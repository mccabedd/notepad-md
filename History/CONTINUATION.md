# NotePad-MD — Continuation Prompt

Paste this whole file as your first message to Claude (or another coding AI) on the new PC, inside this unzipped project folder, to pick up exactly where this session left off.

## What this project is

A Notepad-like desktop app for viewing and editing Markdown (`.md`/`.markdown`/`.txt`) files, with a live, directly-editable preview pane. Built with **Rust + Tauri v2** (native OS WebView2 on Windows, no bundled Chromium) — the whole app is a single ~3–4 MB executable instead of the 250–300 MB an Electron equivalent would produce.

- `ui/` — static frontend: `index.html`, `renderer.js` (all app logic, no framework), `styles.css`, `vendor/` (marked.js for Markdown rendering, turndown.js + turndown-plugin-gfm for HTML→Markdown conversion). This is the whole UI; there is no build step for the frontend, it's loaded directly by the WebView.
- `src-tauri/` — Rust backend: `src/main.rs` (native menu setup + all `#[tauri::command]` file-I/O / OS-integration commands), `Cargo.toml`/`Cargo.lock`, `tauri.conf.json`, `capabilities/default.json`, `icons/`.
- `README.md` — user-facing feature list and build instructions, kept up to date with every change.
- `sample.md` — a sample file for manual testing.

## Prerequisites to build (Windows)

- [Rust](https://rustup.rs) (stable, MSVC toolchain)
- MSVC Build Tools ("Desktop development with C++")
- On this dev machine, `cargo` wasn't on PATH by default in the shell used for builds — had to run `$env:PATH += ";$env:USERPROFILE\.cargo\bin"` before `cargo build` in PowerShell. Check if the new machine needs the same workaround.

```bash
cd src-tauri
cargo build --release
```

Executable lands at `src-tauri\target\release\notepad-md.exe` (the `target/` directory is NOT included in this zip — it's regenerated by the build and is huge; first build will download/compile dependencies including `tauri`, `tauri-plugin-dialog`, `tauri-plugin-clipboard-manager`, and `open`).

For faster iterative dev builds: `cargo run` from `src-tauri/`.

## How this app evolved (so you understand *why* things are the way they are)

This started as an Electron app and was rewritten from scratch in Rust/Tauri for size reasons. Development proceeded in rounds of user feedback, roughly:

1. **Phase 0** — Initial Rust/Tauri rewrite. Removed on-screen toolbar (menu-only access), made the Markdown preview directly editable with two-way sync back to the raw source, thin theme-colored scrollbars/caret.
2. **Phase 1** — Added a toggleable toolbar (off by default, View > Toolbar), made the editable Preview the default view, added 4 layout modes (Preview Only / Edit Only / Preview Left+Edit Right / Edit Left+Preview Right) with a resizable split divider.
3. **Phase 2** — Added a multi-document tab bar (only appears when >1 doc is open) with per-tab close buttons, dirty-dot indicator, `Ctrl+Tab`/`Ctrl+Shift+Tab` to cycle, `Ctrl+W` to close.
4. **Phase 3** — Fixed cut/copy/paste toolbar icons, fixed a broken Find feature, added preview-pane line numbers, removed a redundant "Task" toolbar command (kept Checklist), replaced a blocked native `<select>` heading dropdown with H1–H4 buttons.
5. **Phase 4** — `Ctrl+T` toolbar toggle; Table/Code toolbar icons; a hover-reveal copy button on code blocks in the preview; fixed a Find bug where `window.getSelection().addRange()` was stealing focus (replaced with non-focus-stealing `<mark>`-wrapping of matches); converted all toolbar icons from emoji to monochrome `stroke="currentColor"` SVGs (so they adapt to light/dark theme); **moved all keyboard shortcut handling into a single JS `document.addEventListener('keydown', ...)` handler as the one source of truth**, and set the native Tauri menu's accelerator strings to `None` to stop them double-firing with the JS handler; added `.txt` to the Open-dialog filter and CLI-arg handling.
6. **Phase 5** — User reported the menus had lost their shortcut-hint text (a side effect of #4's `None` accelerators) — restored `Some("CmdOrCtrl+...")` accelerator strings on the native menu items *purely so the hint text displays again* (the JS handler is still what actually executes every shortcut; empirically, on this Windows/WebView2 setup, native menu accelerators do not intercept keystrokes before the webview sees them, so there's no double-fire — a debounce guard (`debounceAction` helper in `renderer.js`) was added to the toggle-style actions as cheap insurance anyway). Also: removed toolbar-visibility `localStorage` persistence entirely so the toolbar is unconditionally hidden on every launch; added clickable links in the preview that open in the system's default browser via a new `cmd_open_url` Tauri command (uses the `open` crate, scoped to `http://`/`https://` only, no shell string interpolation); fixed the code-block copy button so it stays visually pinned at the top-right of the block while the code scrolls horizontally underneath it (moved `overflow-x: auto` from `<pre>` onto the inner `<code>` element, since the button is positioned relative to `<pre>`).
7. **Phase 6 (most recent, small follow-up)** — Changed the Find shortcut from `Ctrl+H` to `Ctrl+F`. Changed the Increase Font Size menu's displayed shortcut from "Ctrl+=" to "Ctrl++" — this required manually embedding the hint text in the menu item's title as `"Increase Font Size\tCtrl++"` with the accelerator itself set to `None`, because the underlying Win32 menu library (`muda`, via Tauri) has no way to *display* "+" for that physical key — it always renders the `Equal`/`Minus` key codes as literal `=`/`-` text regardless of what accelerator string you pass it. (Decrease Font Size stays `Ctrl+-`, which already displayed correctly.) The actual keybinding logic for both was never affected — the JS handler already matched on `e.key === '=' || e.key === '+'` and `e.key === '-'`.

8. **Phase 7 (new PC)** — Rebuilt on a new machine, put on GitHub (`mccabedd/notepad-md`), new purple notes icon, v1.0 release notes. Fixed `Ctrl+Alt+1–4` to match `e.code` (AltGr layouts).
9. **Phase 8** — Drag-and-drop opening, session restore (no close prompt), `*` unsaved marker left of the tab name, pinned tabs, red active-tab bar, always-visible tab bar with ‹ › overflow buttons and a tab right-click menu, per-tab layouts, right-hand view sidebar, syntax colouring for 12 languages (highlight.js), UK/US spellchecking (Typo.js), encoding/line-ending preservation. Verified with an automated DevTools-protocol harness (48 feature checks + 81 shortcut checks), not by hand.

10. **Phase 9** — Ctrl+wheel zoom and per-tab font size, wheel scrolls tabs like the arrows, Save/Save As on the tab menu, BBCode (grammar + read-only preview), remembered state moved into session.json (window geometry too), bottom find bar with an Advanced pane modelled on the Noxturnal Monitoring Tool's Timeline (From/To/Find/Hide filters, regex, all-tabs, sortable/resizable virtualised grid, Timeline-style context menu, coloured bookmarks with block navigation, Add Bookmarks, Reset, Maximise), editor bookmarks (Ctrl+F2/F2).
11. **Phase 10** — Settings dialog (Ctrl+,), word wrap (Alt+Z), menu bar toggle (Alt), sidebar toggle (Ctrl+Shift+E), status bar toggle, table editing in the preview, "restore session" setting with save-on-close prompt.

12. **Phase 11** — "Maximize" wording + ✕ on the Advanced pane, view order Edit/Preview/Edit-Preview/Preview-Edit, Settings Import/Export, Register File Types, About menu with Check for Updates (self-update), per-tab preview mode (MD/BB sidebar button, status-bar language menu).

13. **Phase 12 (v1.0.1)** — Empty untitled tabs survive a restart, and a new tab takes the lowest free "Untitled N" number. Single instance: a second launch hands its files to the running window (`src-tauri/src/instance.rs`: named mutex per data folder + loopback TCP with a token in `instance.json`; the updater relaunches with `--after-update` so the new copy waits for the old one instead of forwarding to it). Insert Image toolbar button; local images in the Markdown preview are served by a `localimg` custom protocol (`http://localimg.localhost/<encoded path>`, image types only) and keep their written path in `data-md-src` so preview edits round-trip. Tabs can be dragged to reorder (mouse events, not HTML5 DnD, because Tauri's file-drop handling swallows HTML5 drag events; pinned and unpinned tabs stay in their own groups).

14. **Phase 13 (v1.0.2)** — Java, CSS, C, C#, C++ languages (grammars were already in the bundled highlight.js). Settings > Files checkbox for an Explorer right-click verb "Edit in NotePad-MD" (`HKCU\Software\Classes\*\shell\NotepadMD.Edit`, Icon = exe,0; `cmd_set_context_menu` / `cmd_context_menu_status` in system.rs; honours NOTEPADMD_REG_ROOT). Classic verbs only show under "Show more options" on Windows 11; the compact menu would need an MSIX sparse package + IExplorerCommand.

## Key architectural decisions to preserve (don't accidentally re-break these)

- **JS `keydown` handler in `renderer.js` is the single source of truth for every keyboard shortcut.** Native Tauri menu accelerator strings in `main.rs` are cosmetic hint text only — never assume setting one is "wiring up" a shortcut; the JS handler (search for `document.addEventListener('keydown'` in `ui/renderer.js`) must also be updated.
- **Ctrl+Alt shortcuts must match on `e.code`, never `e.key`.** On Windows, Ctrl+Alt = AltGr, so `e.key` is layout-dependent (Ctrl+Alt+4 is `€` on a UK keyboard, `@`/`²`/`³` on others). The layout-mode handler maps `Digit1`–`4` / `Numpad1`–`4` to modes.
- **Remembered state lives in session.json, not localStorage.** The window is destroyed right after the final save on close, and WebView2 can lose unflushed localStorage writes (this is why line numbers were "forgotten"). `captureUi()` / `applyUi()` in `renderer.js` hold everything (theme, line numbers, toolbar, spelling, window geometry, find state, `settings`). Window size is saved as the INNER size because `setSize()` sets the inner size.
- **The window starts hidden** (`"visible": false`); `restoreWindow()` applies the saved geometry then shows it. A Rust thread shows it anyway after 3 s.
- **Close flow:** `close-requested` → JS calls `cmd_close_ack` (so the 4 s Rust safety timer won't destroy the window while a save prompt is open) → save session → `cmd_force_close`. If the user cancels a save, `cmd_close_cancelled` resets the state.
- **Script load order matters:** `bbcode.js`, `find.js`, `settings.js`, `table.js` load before `renderer.js` and only touch renderer globals inside functions.
- **Edits made from code (find/replace) must not use `execCommand` when the editor can't take focus** (Preview Only layout) — it would type into whichever input has focus. See `applyEdit()` in `find.js`.
- **Bookmarks are keyed by line index** and re-mapped on every content change by `adjustLineAnchors()` (find.js), called from `markDirty()`.
- **Menu bar:** toggled by tapping Alt alone (JS keydown/keyup) → `cmd_set_menu_visible` (Rust `window.hide_menu()/show_menu()`).
- **View order is Edit, Preview, Edit/Preview, Preview/Edit** everywhere (sidebar, View menu, Settings, `Ctrl+Alt+1..4`) — changed at the user's request in Phase 11.
- **Per-tab language** (`doc.lang` + `doc.langOverride`) drives both colouring and the preview renderer; `setDocLanguage(null)` = auto-detect from the extension. `langOverride` is saved in the session.
- **Self-update** (`system.rs`): GitHub latest-release API via `curl.exe`, SHA-256 via `certutil`, then rename running exe to `.old`, move the new one in, spawn it, `app.exit(0)`. The page saves the session first. Test hooks: `NOTEPADMD_UPDATE_URL` (may point at a `file:` JSON; `file:` downloads are only allowed when it is set) and `NOTEPADMD_REG_ROOT` (registry root for file-type tests). No new crates: `winreg` was already in the tree; builds can use `--offline`.
- **Tab bar is always visible** (user request, Phase 8) — it no longer hides when only one document is open.
- **Toolbar visibility IS remembered now** (the user asked for it in Phase 9 — earlier phases deliberately started it hidden every launch). It is off by default.
- **Editor = transparent `<textarea>` over a coloured `<pre id="editor-highlight">`.** Syntax colours (highlight.js) and spelling underlines live in the `<pre>`; the two elements must keep identical font, padding, line-height, wrapping and scrollbar width (see `.editor, .editor-highlight` in `styles.css`). Never let overlay styles change glyph widths (no bold/italic there).
- **Per-tab state lives on the doc object** (`layoutMode`, `pinned`, `lang`, `encoding`, `eol`, `savedContent`). `setLayoutMode()` changes only the active tab; `applyLayout()` just applies. `dirty` = `content !== savedContent`.
- **Session restore**: the window close always goes through JS (`close-requested` → `saveSessionNow()` → `cmd_force_close`); a 4-second Rust watchdog force-closes if the page never answers. Session JSON is `%APPDATA%\com.notepadmd.app\session.json`; the `NOTEPADMD_DATA_DIR` env var redirects it (used by automated tests). Clean file tabs are re-read from disk; only unsaved/untitled text is stored.
- **Spellcheck** runs in `ui/spell-worker.js` (Typo.js + Hunspell dictionaries in `ui/vendor/dict/`). Editor marks are `.spell-err` spans in the overlay; preview marks use the CSS Custom Highlight API (`CSS.highlights 'spell'`) so the editable preview DOM is never modified.
- **Native drag-drop is on** (`dragDropEnabled: true`), handled via the `tauri://drag-drop` event. This means HTML5 drag-and-drop inside the page (e.g. dragging selected text) is not available on Windows.
- **External links**: only `cmd_open_url` (Rust, `open` crate, http/https-only validation) may open URLs — don't shell out or use `window.open`.
- **Code-copy-button CSS**: the scroll container for code blocks is `.preview pre code` (not `.preview pre`) — if you touch that CSS, keep the button's positioning ancestor (`<pre>`) non-scrolling.
